## 3. scoped 标识带来的连带影响（本轮主要工作量）

需求给出 `{"pkg":"{@scope}/{name}","ver":"{version}","dir":"packages/{@scope}/{name}/{version}"}`。落地时按下述方式展开：

### 3.1 路径与枚举

- `@scope/name` → 落盘 `packages/@scope/name/`；`@scope` 是**容器目录**，本身不是包。
- 枚举规则：`packages/*/` 不以 `@` 开头 = 无 scope 包；以 `@` 开头 = scope 容器，其子目录才是包。
- detect 的路径解析：包名段数从「固定 1 段」变为 1 或 2 段（按首段是否 `@` 开头判定）。

### 3.2 三处命名空间必须 slug（这是需求里「job 名也需要调整」的具体落点）

`@` 与 `/` 不能出现在 job 名、artifact 名、渲染目录中：

```
slug(pkg) = 去前导 "@"，"/" → "-"     # @scope/binding-riscv64 → scope-binding-riscv64
slug(ver) = 原样
```

| 用途 | 形态 |
|---|---|
| job 名 | `build (scope-binding-riscv64 @ 1.0.0-rc.1)` |
| artifact 名 | `scope-binding-riscv64-1.0.0-rc.1-riscv64` |
| 渲染目录 | `.rendered/scope-binding-riscv64/1.0.0-rc.1/action.yml` |

### 3.3 一个不显眼但会直接炸的点：YAML 里的 `@`

`@` 是 YAML 保留指示符，**出现在标量开头即非法**。模板若写 `name: {{npm.name}}`，scoped 情况会渲染成 `name: @scope/...` → 解析失败。因此新增模板约定：**凡以变量开头的标量一律加引号**（`name: "{{npm.name}}"`）。已计入 R10 与风险 R-f。

## 4. D16「复用 PR artifact」的难点与设计

需求已明确「riscv 构建耗时较长，没必要构建两遍」。实现上的真正难点不是下载，而是**定位**：

- 合并提交 SHA ≠ PR head SHA，无法用 commit 直接命中 PR 侧的 artifact。
- 因此需要显式定位链：`commits/{merge_sha}/pulls` → PR head SHA → `gh run list --commit <head_sha>` → `gh run download <run_id>`。

设计中加入**双重回退**（否则复用会比重建更危险）：

| 回退 | 触发条件 |
|---|---|
| 定位失败回退 | 直推 main、强推、PR 未跑过构建、artifact 超保留期 → 重建 |
| **有效性校验回退** | `git diff <pr_head>..<merge_sha> -- packages/<pkg>/ .github/workflows/template.yml` 非空 → 产物基于旧输入，重建 |

第二条是本轮新增的判断：两个 PR 先后合入时，后者的产物可能是基于前者合入**前**的 common 补丁构建的 —— 复用会发布一个与仓库当前配方不一致的产物。这类错误极难在事后发现，必须在发布前拦住。

## 5. D13「生成 publish」时补出的一个必要环节

原草案把 publish 视为「发一个文件」。实际上原生预编译包是一个**独立 npm 包**，若不构造最小 `package.json`（`name`/`version`/`os`/`cpu`/`main`），发出去的包无法被消费（缺 `os`/`cpu` 会装到错误平台）。因此生成的 publish 步骤包含：

1. 组装最小平台包目录（拷产物 + 写 `package.json`）
2. **幂等**：`npm view <name>@<version>` 命中即跳过
3. **scoped 必带 `--access public`**（scoped 默认 restricted，否则发布失败）
4. token 经 job `env` 注入
