## 1. 为什么写这份记录

计划（`.dsh/plan.md`）定的是「怎么做」，这一轮把它变成可运行的代码，过程中有六处必须偏离计划文本，另有两处是实测踩出来的坑（会在真 CI 上再次咬人）。偏差与坑都记在这里，便于你在 L3 前决定是否接受。

## 2. 做了什么

### 2.1 配方库 `scripts/recipe_lib.py`（新增）

- `Target`：`(pkg, ver, path)`，派生 `slug_pkg`（去掉 `@`、`/`→`-`）、`artifact_name`、`ident`。
- `split_recipe_path()`：scoped 名占两段路径（`@scope/name/1.2.3`），返回 `(pkg, ver)`。
- `validate_stat()`：三途径至少一条、`upstream.ref` 不可变、`source.sha256` 必填且 64 位十六进制、`npm_publish` 每项 `name/version/dir` 齐备、`role: binary` 必须带 `os`+`cpu`、`requires` 必须指向本配方内的包且版本一致、**`version` 必须等于版本目录名**、至少一个 `role: main`。
- `resolve_layers()`：同名文件整份替换（版本层胜）、异名继承、补丁 common 在前版本在后按文件名排序、`patches/.disable` 按名单剔除、点文件不算补丁。
- `repository_problems()`：空包目录、版本目录缺 `.stat`、包目录里散落文件——一律报错。

### 2.2 渲染器 `scripts/render.py`（重写）

- 缩进感知替换：多行值的续行按占位符所在行缩进补齐，块标量不再被写坏；空行不补缩进。
- `{{#if key}} / {{#unless key}}` 可嵌套块：可选步骤整段消失，而不是留下空 `run:`。未知键、未闭合、错配闭合都报错。
- 未解析占位符 = 报错（不再静默留 `{{x}}`）。
- `.stat` 展平为点路径变量，外加 `pkg.*` / `recipe.dir` / `src.dir` / `steps.dir` / `has.patches`；`--override key=value` 支持列表下标（`npm_publish.0.registry=...`）。
- 生成 `fetch`：upstream→source→npm 三条路线按优先级降级，未配置的路线是返回 1 的桩；upstream 浅克隆失败自动退回完整克隆（裸 sha 无法浅克隆）；npm 路线走 registry 元数据 API 取 `dist.tarball`/`dist.integrity`，scoped 名 `%2F` 编码，校验 sha512。
- 生成 `patch`：common 补丁在前、版本补丁在后；有 `.git` 时用 `git apply --3way`，否则 `-p1`。
- 生成 `publish`：binary 先于 main 并按 `requires` 拓扑排序；`dir` 相对源码树解析；清单三档（custom/generate/verify）；幂等探针前先写 `.npmrc`（私有 registry 的 `npm view` 本身就要鉴权）；发布用**绝对路径**。
- 自校验：渲染结果过 `yaml.safe_load`、`runs.using == composite`、每步有 `shell` 与非空 `run`、fetch/build/test/publish 步骤齐全；不合格不落盘。
- `--out-dir` 同时写出 `action.yml` 与 `steps/*.sh`。

### 2.3 变更检测 `scripts/detect_targets.py`（重写）

PR 三点 diff、push 两点 diff、`before` 全零即全量、模板变更全量、`scripts/**` 触发渲染自检、common 展开到该包所有版本、版本目录被删则跳过、选中的版本缺 `.stat` 立即失败；输出 `targets/has_targets/publish/self_check/changed_count`。

### 2.4 golden 快照（L0）

`tests/golden/bufferutil-4.2.0/` 存参考配方的渲染结果（`action.yml` + 四个脚本）。模板或渲染器一改，单测立刻给出 unified diff；确认是有意变更后用 `python3 tests/regen_golden.py` 刷新并一起提交。为此渲染器新增 `--steps-dir`，让写盘位置与 action 里引用的路径解耦，否则快照会带上临时目录名。

### 2.5 模板与工作流

- `.github/templates/action.template.yml`：五步 action；qemu 与 riscv64 容器固定在模板内（D7），镜像可用 `RISCV_IMAGE` 覆盖；publish 由 `inputs.publish` 门控。
- `.github/workflows/build.yml`：单文件双触发；detect → build（矩阵、`max-parallel: 3`）→ 上传 artifact；`permissions.packages: write`；删除旧的 `pr-run.yml` 与放错位置的 `template.yml`。

### 2.6 首个真实配方与镜像

- `packages/@ruyisdk/bufferutil/4.2.0/`：`upstream` 指向 `websockets/bufferutil@v4.2.0`；`build` 用 `node-gyp rebuild` 并把产物放进 `prebuilds/linux-riscv64/`；`test` 断言产物是 RISC-V ELF，并**隐藏 `build/`** 后验证 `node-gyp-build` 能解析到 prebuild、`mask/unmask` 往返一致。
- `docker/riscv64-toolchain.Dockerfile`：`debian:trixie-slim`（riscv64）+ build-essential/nodejs/npm/python3/node-gyp。

## 4. 与计划的偏差（待你确认）

1. **产物形态**：`action.yml` + `steps/*.sh`，而非把 shell 塞进 YAML 块标量。块标量里既不能写 heredoc（终止符必须顶格），引号转义出错又要到运行期才炸；脚本落盘后可静态检查。
2. **publish 在宿主执行**，不进 riscv64 容器：发布不需要模拟，容器只会更慢更绕。
3. **矩阵 job 的 `uses:` 用固定 `.rendered/action`**：GitHub 的 `uses:` 不接受表达式；矩阵 job 各有独立 workspace，固定路径天然隔离。
4. **清单档位收敛为三档**（custom/generate/verify）：`create` 与 `rebrand` 实现上是同一段逻辑。
5. **S0 裁剪为单一真实配方**：三途径降级、`source`+sha256、common 补丁 + `.disable`、A/B 双包、`verify` 拦截改用 L0 夹具与 L2 假配方覆盖，避免往首包塞假补丁。
6. **新增两条硬规则**：`npm_publish[].version` 必须等于版本目录名；仓库结构问题在 detect 阶段硬失败。

## 5. 实测踩到的坑

1. `npm publish src/.` 被 npm 当成 GitHub 简写（`ssh://git@github.com/src/..git`），两段相对路径都会中招 → 改为 `cd` 后取绝对路径发布。
2. npm 元数据会把 `optionalDependencies` 并入 `dependencies` → 「不丢字段」的断言改成子集比对 + 其余字段逐字比对。
3. verdaccio 容器以非 root 运行，宿主 `rmtree` 删不掉它的文件 → 清理改由容器执行；配置里的 `uplinks: {}` 写成 `{{}}` 会让 verdaccio 直接崩（YAML 流映射嵌套）。
4. compose 模板里 `@` 开头的标量必须加引号，否则 YAML 解析成 tag——渲染器自解析会把这类错误当场抓出来（已写成 L0 用例）。
